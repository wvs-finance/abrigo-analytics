## Goal

Implement E10 GSPS v0.4 as a fully descriptive iteration: produce the **FX-variance-share
sensitivity surface** (the share `Var(Δlog FX) ÷ Var(Δlog cost)` reported as a function
across the anchored Q-volume range) for the declared representative Web3-data-analyst
profile, compared against an **ex-ante-pinned fitted-hedge break-even threshold**. The
load-bearing build is the R6 NHPP query-workflow simulation engine, resurrected from a
19-task spec that was never coded. E10 v0.4 makes **no inferential β claim** — the
deliverable is a surface (a description), not a verdict point.

## Architecture

Three-tier `simulations/e10_gsps/` sub-package per CLAUDE.md (`types/` Value tier;
`modules/` Callable tier; `utils/` IO Boundary tier; `tests/`). Six execution phases
mapping 1:1 onto the spec §10 sub-task order E10.0–E10.5, plus a pre-phase scaffold
(Phase 0) and a gated ex-ante break-even pinning sub-step (Phase 2.5). Notebooks live in
`notebooks/e10_gsps/`. Every phase task dispatches a named specialized subagent; the
foreground session orchestrates and verifies, never authors.

## Plan principles (carried forward from `feedback_*.md`)

- **Code-agnostic plan.** Per `feedback_no_code_in_specs_or_plans.md` and
  `feedback_no_inline_signatures_in_plans.md`, this plan contains NO inline code, NO
  function signatures, NO Python. Every task is described as *what to achieve* and *how
  it is verified*, never *what code to write*. Type/module names appear only as
  artifact identifiers, never as signatures.
- **Data-visibility gate FIRST** — no modeling work begins until §0 DV-PASS-FREE is
  frozen at execution start.
- **Specialized agents per task** — every task names the specialized subagent that
  executes it; the foreground orchestrates and verifies (§9).
- **Task-type tagging** — per `feedback_plan_flags_brainstorm_tasks_nonbypassable_data_gates.md`,
  every §1 / §2.5 / §4 task carries a `[brainstorm-judgment]` or `[mechanical-execution]`
  tag (a task with both gets the mixed tag on its respective sub-steps). A
  `[brainstorm-judgment]` task instructs the dispatched specialist to deliberate the
  choice, record a 4-part decision-citation (reference / why / relevance / connection),
  and surface load-bearing choices to the user before locking — never mechanically pick
  the first option. Data-fetch tasks additionally state the non-bypassable HALT branch.
- **Descriptive posture carried into every phase** — no phase may produce or imply an
  inferential β verdict; the words "PASS", "confirmatory", and inferential-β language
  are firewall-banned from main-line code (Phase 0).
- **STRICT TDD** — no implementation task fires without a prior failing-test harness.
- **Notebook trio checkpoint + decision-citation block** carried forward unchanged.
- **No inline signatures** — tasks describe behavior, invariants, dispatch.
- **Block-protocol on review** — convergent reviewer BLOCK findings are structural;
  scoped re-review on changed sections; never wave through a BLOCK.
- **Three-tier reproducibility** — Tier 1 panels / Tier 2 raw pulls / Tier 3 builder.

## §4. Ex-ante break-even pinning (Phase 2.5 — the Stage-1/Stage-2 firewall mechanism)

This is a discrete, gated sub-step, called out separately because it is the mechanism
that restores the Stage-1/Stage-2 firewall (CORRECTIONS-E10-4 Fix 2 / Model QA C-2,
N-2). It fires **after Phase 2 (E10.1) and strictly before Phase 3 (E10.2)** — the
break-even threshold is a Stage-2 economic constant frozen *before* the Stage-1 surface
is ever computed, so it can carry no Stage-1 estimation content.

**Spec-traceability note (per CORR-E10P-5 / RC STRONG-1).** Phase 2.5 has no spec §10
sub-task number. It implements a §13-resident step (the §13.2 / §4.4 ex-ante break-even
pinning) that spec §10 step 3 (E10.2) *assumes already done* — not a §10 sub-task. The
plan inserts it between Phase 2 and Phase 3 precisely to honor that assumed ordering.

**Why a discrete gated step.** v0.3 fitted the convex payoff to the §4 *decomposition
estimate*, making the §8 break-even threshold depend on a Stage-1 result — a
post-data-threshold path that breached the firewall. v0.4 corrects this by pinning the
threshold ex ante from option-premium economics, independently of the §4 decomposition.

**Firewall bright line (per CORR-E10P-6 / RC STRONG-2 + Model QA W-1).** Phase 2.5 may
consume the Phase-2 anchored Q-volume *range* (a calibration input carrying no §4
decomposition content) and *published long-run FX-vol regime characterizations*. It may
NOT consume any Phase-3 §4 decomposition output, nor the realized within-window variance
of the E10 panel itself. "Informed by historical FX-vol regimes" means published regime
characterizations only — not a peek at the panel's realized variance. The Stage-2
firewall (Phase 0.11) mechanically enforces the payoff-fitting half of the line; the
specialist enforces the published-vs-realized half via the decision-citation record.
